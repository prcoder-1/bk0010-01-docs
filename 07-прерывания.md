# 7. Прерывания и векторы

> **Источники главы**
> * **[РСП § 5.1]** «Адреса векторов прерывания» (с. 17) — нормативный перечень источников
>   прерываний; **[РСП, Прил. 1]** — коды команд прерывания.
> * **[З]** «Векторы прерываний», «Векторы прерывание и программирование» — приоритеты,
>   таблица из ремонтной документации, различение «СТОП»/зависание по разряду 02
>   регистра 177716, работающий пример отладчика на T-разряде.
> * **[ВМ1]** § 7.3 — таблица исключений и прерываний **на уровне кристалла**:
>   приоритеты, маскирование разрядами PSW 7/10/11, пультовый режим.
> * **[ПЗУ]** — штатные адреса обработчиков векторов 4, 30, 60, 274.

## 7.1. Механизм прерывания

**Прерывание** — приостановка выполнения текущей задачи и переход к обслуживанию внешнего
устройства или программного запроса.

Последовательность действий процессора при прерывании:

1. Завершается выполнение текущей команды (кроме прерывания по «СТОП», см. ниже).
2. В стек заносится текущее **ССП (PS)**.
3. В стек заносится текущий **PC** — адрес следующей команды.
4. Из первого слова вектора в PC переписывается адрес программы обработки.
5. Из второго слова вектора в PS переписывается новое ССП (в том числе приоритет).

**Вектор прерывания** — два подряд идущих машинных слова в системной области ОЗУ:
первое — адрес программы обработки, второе — ССП для неё. Вектор именуется по адресу
первого слова. Адреса векторов зафиксированы аппаратно в процессоре.

Возврат выполняется командой `RTI`, которая восстанавливает из стека PC и PS
(включая флаги CVZN, T-разряд и приоритет). Эквивалентно:

```asm
        MOV     (SP)+,PC        ; восстановить адрес команды
        MTPS    (SP)+           ; восстановить ССП
```

Аппаратное прерывание обслуживается, только если **приоритет текущей задачи (разряды
05–07 PS) ниже приоритета устройства**. Иначе запрос «зависает» до снижения приоритета.
Командные (программные) прерывания на приоритет не смотрят и удовлетворяются всегда.

Векторы попадают в системную область из ПЗУ при запуске системы; они же восстанавливаются
командой `EMT 14`.

## 7.2а. Что происходит на уровне кристалла [ВМ1 § 7.3]

Таблица §7.2 описывает векторы **с точки зрения программы на БК**. Техническое описание
процессора даёт картину уровнем ниже, и несколько её деталей практически важны:

* **Маскирование.** Прерывания от устройств (nIRQ2 → вектор 100, nIRQ3 → 270,
  ВЕ-таймер → 270, векторное nVIRQ) запрещаются разрядом **PSW7** либо **PSW10**
  (достаточно одного). Разряды **PSW10 и PSW11** дополнительно управляют обработкой
  зависания шины и пультового режима. Утверждение «в БК используется только младший байт
  PSW» верно для **монитора**, но не для кристалла.
* **Зависание шины ведёт себя по-разному.** При PSW11 = 0 и PSW10 = 0 — исключение
  по вектору **4** с сохранением в стеке. Если хотя бы один из PSW10/PSW11 установлен —
  переход в **пультовой режим** по вектору `160002` с сохранением PSW/PC по адресу
  `177674`.
* **Пультовый режим.** Векторы `160002` (аппаратный останов и `HALT`), `160006`
  (двойное зависание), `160012` (зависание при получении вектора в цикле nIAKO).
  `HALT` — **единственное программное исключение, переводящее в пультовой режим**.
  В БК область 160000+ занята ПЗУ МСТД, поэтому туда и попадает управление.
* **Вектор 270 разделяют два источника**: nIRQ3 и встроенный ВЕ-таймер (последний —
  только в К1801ВМ1Г, и дополнительно маскируется битом `MON` регистра управления
  таймером). В БК не задействован ни один — ячейки 270/272 свободны.
* **`WAIT` и T-бит.** В режиме ожидания по `WAIT` T-бит не вызывает немедленного
  исключения: процессор ждёт прерывания, и любое незамаскированное (ACLO, IRQ1, TVE,
  IRQ2, IRQ3, VIRQ) выводит из режима с переходом по своему вектору.
* **nIRQ1 и nVIRQ чувствительны к уровню, а не к фронту.** Если уровень не снят после
  обработки, немедленно возникает новый запрос.
* **Начальный пуск.** После аппаратного сброса процессор читает стартовый адрес
  из старшего байта регистра `177716`, а PSW устанавливает в `340`.

Полная таблица исключений в порядке приоритета — в
[04-процессор-К1801ВМ1.md](04-процессор-К1801ВМ1.md), §4.5.

## 7.4. Вектор 4 — «СТОП» и зависание

Диагностика в МСД:

* **`ЗВ(адрес)`** — зависание. Возникает при попытке записи по адресу ПЗУ либо чтения/записи
  по несуществующему адресу (устройство не выдало сигнал СИП). Если зависание вызвано
  директивой МСД (например, `100000А377И`), выданный адрес и есть адрес зависания.
  Если работала программа пользователя — **выданное число ничего не значит**, информацию
  несёт только сам факт сообщения «ЗВ».
* **`НК`** — неправильная команда (вектор 10).

### Перехват «СТОП»

Простейший вариант — заглушка — **работать не будет надёжно**:

```asm
V4:     RTI                     ; НЕДОСТАТОЧНО!
```

При нажатии «СТОП» процессор может **не закончить** выполнение текущей команды, хотя в стек
попадёт PC следующей. Возврат по `RTI` в этом случае может привести к зависанию.

Правильный подход — передать управление на «холодный» (повторный) вход программы,
предварительно восстановив стек:

```asm
V4:     MOV     #1000,SP        ; восстановить вершину стека
        JMP     RBG             ; повторный вход в программу
```

Восстановление SP обязательно: без `RTI` стек при каждом нажатии «СТОП» засоряется
парой ССП+PC и рано или поздно исчерпается.

Вариант с сохранением возможности выхода:

```asm
V4:     MOV     #1000,SP        ; восстановить SP
        EMT     6               ; ожидание нажатия клавиши
        CMPB    #40,R0          ; «ПРОБЕЛ»?
        BEQ     0               ; да — на выход
        JMP     RBG             ; иначе — перезапуск программы
0:      EMT     14              ; восстановить все векторы и режимы
        HALT                    ; останов и выход в ПМ
```

Установка вектора в начале программы:

```asm
1000    012706 001000   MOV   #1000,SP    ; установить стек
1004    104014          EMT   14          ; начальное состояние экрана
1006    012737 001000 000004  MOV #1000,@#4  ; «СТОП» → перезапуск с 1000
```

## 7.5. Вектор 10 — резервный код

Прерывание возникает при встрече кода, отсутствующего в наборе команд ЦП. Применения:

* **Фокал** обрабатывает через вектор 10 свои псевдокоманды и функции с кодами 7000…7377,
  а также эмулирует команды плавающей арифметики.
* Аналогичная система расширенной арифметики реализована в ПЗУ КНГМД.
* Пользователь может ввести собственные «дополнительные команды процессора», выбрав
  свободные коды.

## 7.6. Вектор 14 — T-разряд и BPT. Как устроен отладчик

Записать 1 в T-разряд командой `MTPS #20` невозможно. Приём: вызвать командное прерывание
(`BPT` — по тому же вектору 14), в обработчике **подменить сохранённое в стеке ССП**,
установив в нём T-разряд, и выйти командой `RTT`.

Команда `RTT` отличается от `RTI` тем, что прерывание по T-разряду после неё **не наступает
немедленно**: сначала выполняется следующая команда, и лишь потом происходит прерывание.
Именно это и нужно для трассировки.

Полный работающий пример простейшего отладчика:

```asm
; Запуск отладчика
        MOV     #BPT1,@#14          ; записать пусковой вектор @#14
        BPT                         ; прерывание по вектору @#14
; Демонстрационная программа
        MOV     #1,R1
0:      ASL     R1
        ADC     R1
        BR      0
; Трассировка
TRS:    MOV     R0,-(SP)            ; сохранить используемые
        MOV     R3,-(SP)            ; отладчиком
        MOV     R4,-(SP)            ; регистры
        MOV     R5,-(SP)
        MOV     'A=',R0             ; «A=»
        EMT     16
        SWAB    R0
        EMT     16
        MOV     10(SP),R3           ; извлечь PC из стека (8 байт от вершины)
        MOV     R3,R4
        CALL    @#163220            ; печать адреса (п/п МСД)
        MOV     'K=',R0             ; «K=»
        EMT     16
        SWAB    R0
        EMT     16
        MOV     @R3,R4              ; код команды по этому адресу
        CALL    @#163220
        MOV     'R=',R0             ; «R=»
        EMT     16
        SWAB    R0
        EMT     16
        MOV     R1,R4               ; содержимое R1
        CALL    @#163220
        MOV     #12,R0              ; перевод строки
        EMT     16
0:      BIT     #100,@#177716       ; клавиша нажата?
        BNE     0                   ; нет — ждать
        MOV     (SP)+,R5            ; восстановить
        MOV     (SP)+,R4            ; регистры
        MOV     (SP)+,R3
        MOV     (SP)+,R0
; Запись T-разряда, выход из прерывания
BPT1:   BIS     #20,2(SP)           ; T-разряд в сохранённое в стеке ССП
        MOV     #TRS,@#14           ; рабочий вектор @#14
        RTT                         ; выход из отладочного прерывания
        END
```

Ключевые моменты:

* PC лежит в стеке на 8 байт (10 восьм.) от вершины, потому что после него в стек занесены
  ещё четыре регистра — отсюда `10(SP)`.
* Индицируется адрес **следующей** команды — так делают и настоящие отладчики: сначала
  смотрим, что предстоит выполнить.
* Подпрограмма ПЗУ `@#163220` (в МСТД) выводит содержимое R4 шестью восьмеричными цифрами;
  она не сохраняет R0, R4, R5.
* Внутри самого обработчика трассировки нет: при переходе по вектору 14 в ССП переписалось
  второе слово вектора (`@#16`), где T-разряд равен нулю.

**Прозрачность командных прерываний.** При пошаговой отладке любое командное прерывание
(`EMT`, `TRAP`, `IOT`) отрабатывается как одна команда, потому что при переходе по вектору
переписывается ССП и T-разряд сбрасывается. Чтобы «заглянуть внутрь» EMT-диспетчера,
достаточно установить T-разряд **во втором слове** соответствующего вектора.

## 7.7. Вектор 20 — IOT

Полный аналог `EMT`/`TRAP`, но без аргумента в младшем байте. Пример — звуковой сигнал
по одной команде:

```asm
        MOV     #IOT,@#20       ; в начале программы
        ...
IOT:    MOV     #7,R0           ; код «звонок»
        MOV     #100,R1         ; 64д повторов
0:      EMT     16
        SOB     R1,0
        RTI
```

Чтобы обращаться по `IOT` к нескольким подпрограммам, аргумент можно записать словом
**после** команды; диспетчер прочитает его косвенно через сохранённый в стеке PC
и увеличит PC на 2 перед возвратом.

Команда `IOT` предназначена для вызова процедур и обработки ошибок в операционных
системах, поэтому её лучше не занимать: это может помешать работе с дисковыми ОС.

## 7.8. Вектор 24 — авария питания

Аппаратно не задействован: вход ACLO процессора не подключён к устройству контроля питания,
которого в БК просто нет. Программа обработки в ПЗУ, тем не менее, существует — директива
МСД `160714G` выдаёт сообщение «сбой питания».

Прерывание можно вызвать доработкой: подать положительный импульс на вывод 13 микросхемы
D6.4 (К561ЛЕ5), например разрядив на него конденсатор 0,03…0,05 мкФ, заряженный до +5 В.
Прерывание внеприоритетное (как «СТОП»), что позволяет по дополнительной кнопке вызывать
графическую копию экрана и т. п.

> Автор источника **категорически не рекомендует** такую доработку тем, кто редко берёт
> в руки паяльник.

## 7.9. Вектор 100 — внешний таймер / прерывание пользователя

Вход — контакт **В1** разъёма порта УВВ (или А5 разъёма системной шины). Уровни ТТЛ:
«0» — 0…0,4 В, «1» — 2,4…5 В. Прерывание возникает по **заднему фронту** импульса
(переход 1 → 0), если позволяет приоритет процессора (менее 4 — см. оговорку ниже).

Простейший способ вызвать прерывание — подать на контакт В1 «землю» с контактов
А11, В11, А18, В18, А19 или В19 (порт инвертирующий).

Пример счётчика импульсов:

```asm
; Инициализация
        CLR     R1                  ; очистить счётчик
        MOV     #TIM,@#100          ; записать вектор @#100
        HALT
; Обработчик
TIM:    INC     R1
        MOV     R1,R4
        CALL    @#163220            ; выдать показания на экран
        RTI
        END
```

Максимальная частота импульсов при простейшем обработчике — 20–30 кГц, но при этом
почти всё время процессора уходит на обработку прерываний.

Типовые применения: печать копии экрана по кнопке (программа GRAFIX фирмы ALTEC,
резидентный драйвер SCREW ANIRAM-MIRIADA), счётчик расхода ленты магнитофона,
подключение АЦП типа «преобразователь напряжения в частоту».

## 7.10. Векторы 60 и 274 — клавиатура

Вектор **60** — обычные клавиши, вектор **274** — клавиши в регистре «АР2» («НР»).
Приоритет обоих — 4; прерывание удовлетворяется, если приоритет процессора меньше 4.

> ⚠ **«Приоритет 4» — язык PDP-11, а у ВМ1 приоритет однобитный.** В полном PDP-11
> приоритет задают три разряда ССП 07…05, и «меньше 4» означает сравнение трёхразрядного
> числа. В К1801ВМ1 маскирует **только разряд 07** (`I`), а разряды 06 и 05 резервные
> и ни на что не влияют [ВМ1]. Практически формулировки совпадают: «приоритет 4»
> и есть `200` — разряд 07 установлен. Поэтому **«приоритет меньше 4» читайте как
> «разряд 07 сброшен»**. Полная карта разрядов ССП —
> в [04-процессор-К1801ВМ1.md](04-процессор-К1801ВМ1.md), §4.0.
Преобразование 7-разрядного кода из 177662 в код нижнего регистра выполняется благодаря
тому, что для «АР2» предусмотрен отдельный вектор.

Эти векторы почти никогда не изменяются программами пользователя, поэтому они удобны для
внедрения дополнительных директив практически в любую программу. Особенно удобны коды
клавиш «РУС», «ЛАТ» и «ВВОД» в регистре «АР2»: они не обрабатываются почти никакими
программами.

Запрет ввода символов по «АР2» (полезно, чтобы случайное нажатие не переключило
«БЛ.РЕД», «ИНВ.ЭКР» или «РП» и не испортило картинку):

```asm
        MOV     #TN,@#274       ; в начале программы
        ...
TN:     TST     @#177662        ; снять готовность клавиатуры
        RTI
```

Вызов подпрограммы по «АР2»/«ЛАТ» с последующей передачей управления штатному драйверу:

```asm
; Инициализация драйвера
        MOV     PC,R0               ; вычислить адрес супервизора
        ADD     (PC)+,R0            ; в перемещаемом
        .@SQN+2                     ; формате
        MOV     R0,@#274
        HALT
; Супервизор — обработка прерывания по «АР2»
SQN:    CMPB    #17,@#177662        ; клавиша «ЛАТ» по регистру «АР2»?
        BNE     0                   ; нет — выход
        CALL    GRK                 ; графическая копия экрана
0:      JMP     @#101362            ; в штатный драйвер клавиатуры БК
```

Работа с клавиатурой по прерываниям:

```asm
        MOV     #TI,@#60        ; адрес своей программы обработки
        MOV     #200,@#62       ; приоритет 4 — запретить прерывания
        ...                     ; на время работы обработчика
TI:     MOVB    @#177662,R0     ; принять код нажатой клавиши
        ...
        RTI
```

## 7.11. TRAP — командное прерывание пользователя

`TRAP X` (коды 104400…104777) полностью аналогичен `EMT X` (коды 104000…104377), но идёт
по вектору 34. По соглашению `EMT` используется системными программами, `TRAP` —
пользовательскими и исполняющими системами языков.

В интерпретаторе Фокала `TRAP` с нечётным кодом в младшем байте выдаёт сообщение об ошибке
с соответствующим номером, с чётным — вызывает подпрограмму. В трансляторе вильнюсского
Бейсика номер делится **по границе `100`**: `TRAP 0`…`TRAP 77` — код ошибки,
`TRAP 100`…`TRAP 130` — вызов внутренней подпрограммы транслятора, причём параметры
передаются словами, стоящими за самой командой. Разбор диспетчера и таблица номеров —
в [10-бейсик.md](10-бейсик.md), §10.7.

> ⚠ **Следствие для программ в кодах.** Бейсик занимает вектор `34` целиком и
> устанавливает его при каждом запуске. Подпрограмма, вызванная из Бейсика через
> `USR` или `CALL`, командой `TRAP` пользоваться не может — управление уйдёт
> в диспетчер Бейсика.

Простейший TRAP-диспетчер — вывод символа, код которого равен номеру TRAP:

```asm
        MOV     #TRP,@#34           ; установить свой вектор 34
;       MOV     #340,@#36           ; при необходимости — максимальный приоритет
        ...
        TRAP    101                 ; вывести «A»
        TRAP    102                 ; вывести «B»
        ...
TRP:    MOV     R0,-(SP)            ; сохранить R0
        MOV     2(SP),R0            ; адрес возврата из стека
        MOV     -(R0),R0            ; сама команда TRAP
        EMT     16                  ; вывести символ из младшего байта
        MOV     (SP)+,R0
        RTI
```

Экономия: обычный вывод символа — две команды в три слова (`MOV #101,R0` + `EMT 16`),
здесь — одна однословная команда. Сам диспетчер занимает семь слов, поэтому выигрыш
появляется начиная с четвёртого-пятого вывода.

Действия процессора при командном прерывании эквивалентны:

```asm
        MFPS    -(SP)               ; сохранить текущее ССП
        MOV     PC,-(SP)            ; сохранить адрес следующей команды
        MTPS    @#36                ; записать новое ССП
        MOV     @#34,PC             ; перейти на обработчик
```

## 7.12. HALT

Команда `HALT` (код 000000) — это, по существу, командное прерывание по вектору 4.
Она обычно неправильно относится к «командам управления машиной». Дальнейшее поведение
машины целиком зависит от программы обработки вектора 4: в ПМ она выводит «останов»,
в игре — может делать что угодно.

Важно: **изменяя вектор 4, вы одновременно меняете и поведение клавиши «СТОП»**.
