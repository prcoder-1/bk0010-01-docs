# 8. Системный монитор БК-0010-01

> **Источники главы**
> * **[РСП § 5, 6]** «Структура системного программного обеспечения», «Программные запросы»,
>   «Описание функций пускового монитора» (с. 17–24); **[РСП § 7.3, 8.3, 9, 10]** — команды
>   драйверов; **[РСП, Прил. 2]** «Директивы режима отладки» (с. 59–64).
> * **[З]** «Мониторная система диагностики (МСД)», «Операторы прерывания» (полное описание
>   EMT-функций с примерами), «Концепция системных драйверов» (перехват вектора 30),
>   «Временные характеристики» (время исполнения EMT).
> * **[ПЗУ]** — таблица адресов обработчиков всех EMT, листинги начального пуска,
>   инициализации и EMT-диспетчера. **Этих данных нет ни в одном текстовом источнике.**

Содержимое ПЗУ по адресам **100000…117777** называют по-разному: **МОНИТОР**,
**монитор-драйверная система (МДС)**, «виртуальный процессор». Это операционная система
БК: без неё машина не выполняет ни одной операции, включая ввод символа с клавиатуры
и вывод его на экран.

Авторство МДС принадлежит **М. И. Дябину** (Москва, 1983–1985); исходный текст известен
как листинг `DMBK`.

**МДС не менялась с 1985 г. и одинакова во всех моделях БК-0010 и БК-0010-01.** Именно
поэтому программы 1985 года работают на машинах последних выпусков. (МДС БК-0011М с ней
программно несовместима.)

## 8.1. Состав монитора

| Компонент | Что делает |
| --- | --- |
| Программа начального пуска | Инициализация системы при включении питания, передача управления на 120000 |
| **Пусковой монитор (ПМ)** | Диалоговый режим: загрузка и запуск программ в кодах. Приглашение — `?` |
| **EMT-диспетчер** | Разбор команд `EMT n` и вызов нужного драйвера. Адрес — `100112` |
| Драйвер клавиатуры (`DKLAW`) | Обработка векторов 60 и 274, формирование кодов с учётом регистров, ключи, табуляция, автоповтор |
| Драйвер ТВ-монитора (`DTWMN`) | Знакогенератор, текстовая графика, рулон, служебная строка, цвет |
| Драйвер магнитофона (`DMAG`) | Чтение/запись файлов на МЛ, управление двигателем |
| Драйвер ТЛГ-канала (`DTLG`) | Последовательный обмен по телеграфному каналу |

Кроме того, к машине относятся ещё две системные программы, физически расположенные
в **блоке МСТД** (адреса 160000…177577):

* **тест-система** (приглашение `+`) — набор тестов ОЗУ/ПЗУ, клавиатуры, порта,
  знакогенератора и магнитофона;
* **МСД — мониторная система диагностики**, она же **пультовый отладчик**
  (приглашение `¤`) — просмотр и изменение памяти, работа с массивами и файлами,
  запуск и отладка программ в кодах.

## 8.2. Инициализация при включении питания

Адрес начального пуска процессора — **100000** (задан старшим байтом регистра 177716).

Дизассемблирование `bkemu/ROM/bk10_017_mon.rom` [✓ ПЗУ]:

```asm
100000  000167 000254   JMP     100260          ; переход на программу пуска

100260  012706 001000   MOV     #1000,SP        ; установить стек
100264  004767 177650   JSR     PC,100140       ; полная инициализация (= обработчик EMT 14)
100270  004737 120000   JSR     PC,@#120000     ; передать управление на 120000
                                                ; (Бейсик, либо Фокал при МСТД)

100274  004767 177640   JSR     PC,100140       ; вход в ПМ: инициализация…
100300  ...                                     ; …и далее командный цикл ПМ
```

Отсюда сразу следуют два практически важных факта:

* исходное содержимое SP в ПМ — **1000**;
* адрес **100274** — точка входа в пусковой монитор; директива МСД `100274G` переводит
  в ПМ без стирания ОЗУ.

### Что именно делает инициализация (адрес 100140, он же обработчик `EMT 14`)

```asm
100140  005001                  CLR     R1                  ; R1 = 0
100142  012702 000020           MOV     #20,R2              ; 16 слов
100146  012721 100000           MOV     #100000,(R1)+       ; ячейки 0…36 := 100000
100152  077203                  SOB     R2,100146           ;   (адрес перезапуска системы)
100154  012737 100442 000004    MOV     #100442,@#4         ; вектор 4  := ПМ
100162  012737 100112 000030    MOV     #100112,@#30        ; вектор 30 := EMT-диспетчер
100170  012737 000200 000032    MOV     #200,@#32           ; ССП для EMT := 200 (приоритет 4)
100176  012702 000120           MOV     #120,R2             ; 80д слов
100202  005021                  CLR     (R1)+               ; очистить ячейки 40…277
100204  077202                  SOB     R2,100202
100206  104004                  EMT     4                   ; инициализация драйвера клавиатуры
100210  005267 ...              INC     …                   ; настройка переменных
100214  105267 ...              INCB    …                   ;   драйверов
100220  005167 ...              CLR     …
100224  005167 ...              CLR     …
100230  004767 004474           JSR     PC,…                ; инициализация дисплея, очистка экрана
100234  005000                  CLR     R0
100236  104040                  EMT     40                  ; инициализация драйвера ТЛГ
100240  005037 177714           CLR     @#177714            ; очистить порт вывода
100244  012737 000220 177716    MOV     #220,@#177716       ; ТЛГ = 1, двигатель МЛ — стоп
100252  106427 000000           MTPS    #0                  ; приоритет процессора 0
100256  000207                  RTS     PC
```

Из листинга видно точно, **какая часть системной области очищается**: ячейки
**40…277** включительно (80д слов, начиная с адреса 40). Не затрагиваются:

* стек (372…777);
* блок параметров драйвера магнитофона (320…371);
* переменные драйвера магнитофона 300…316.

Это объясняет известное свойство ячейки **316**: она единственная из свободных ячеек,
чьё содержимое не меняется при `EMT 14` (кроме ячеек стека).

## 8.3. Пусковой монитор (ПМ)

**Приглашение: `?`**

> Раздел приведён по **[РСП § 6]** «Описание функций пускового монитора» — в двух
> популярных книгах этот материал пересказан неполно и с искажениями.

Пусковой монитор решает две задачи: **инициализация микро-ЭВМ** по включению питания
(либо при запуске процессора тумблером) и **диалоговый режим** загрузки/запуска программ.

В диалоговый режим ПМ попадает, если ПЗУ с системной программой (адрес 120000) отсутствует
и обращение к нему вызвало прерывание по зависанию, либо по явной команде из системной
программы.

Вход:

* из Бейсика — команда `MON` (достаточно набрать `MON` и «ВВОД»);
* из Фокала — `P M` («Р», пробел, «М», «ВВОД»);
* из МСД — директива `100274G` (без стирания ОЗУ);
* из МСД — `4АЩ100442И` и затем «СТОП» (без стирания экрана и без выхода из режима РП).

### Директивы ПМ

Команды допускают полный и сокращённый формат; в таблице сокращение выделено жирным.
Числовые параметры — восьмеричные.

| Команда | Кратко | Действие |
| --- | --- | --- |
| **М**АГ `[адрес]` | `М` | Загрузка файла с магнитной ленты. Монитор запрашивает `ИМЯ?`. Если адрес не задан — файл грузится по адресу из оглавления на ленте |
| **Л**ИНИЯ `[адрес]` | `Л` | Загрузка файла по последовательному каналу на скорости 9600 бод. Оглавление файла на линии — 4 байта: адрес (слово) и длина (слово) |
| **С**ТАРТ `[адрес]` | `С` | Запуск программы. Если адрес не задан — берётся из ячейки 264 (адрес последней загрузки) |
| **П**УСК | `П` | Передача управления ПЗУ по адресу **140000** |
| **Т**ЕСТ | `Т` | Переход в тест-систему (адрес запуска 160100, блок МСТД) |
| любое слово, начинающееся с латинских `A`…`K` | | Перезапуск системной программы по адресу 120000 (например, `BASIC`) |

### Диалог команды `МАГ` [РСП § 6.1]

```
? МАГ 2000 ⏎
Имя? ИГРА ⏎
```

* Адрес загрузки — восьмеричное число. **Если адрес не указан или равен нулю**, файл
  грузится по адресу из оглавления на ленте.
* Ошибка при наборе адреса исправляется вводом нескольких нулей или пробела, после чего
  вводится полный адрес.
* Имя — не более 16 символов. **Если имя не указано, загружается файл с именем
  из 16 пробелов.** Ошибка в имени исправляется клавишей «ЗАБОЙ».
* После ввода имени нужно подмотать МЛ и нажать «ПУСК» на магнитофоне.
* **При поиске на экран выводятся имена просмотренных файлов.** Имя найденного файла
  не печатается — он сразу читается в ОЗУ.
* По окончании чтения появляется `?`. При ошибке — сообщение **`ОШИБКА`**.
* После загрузки: ячейка **264** — адрес, куда загружен файл, ячейка **266** — его длина
  в байтах.

Существенные подробности, которых нет в популярных книгах:

* **`СТАРТ` передаёт управление командой `JSR PC,<адрес>`**, а не `JMP`. Поэтому запущенная
  программа может вернуть управление монитору обычным `RTS PC`, без перезапуска системы.
* Если файл считан с ошибкой, на экран выдаётся сообщение **`ОШИБКА`**.
* По нажатию клавиши «СТОП» ПМ устанавливает указатель стека на 1000, приводит системный
  порт в исходное состояние, инициализирует драйверы и переходит в диалоговый режим.
* Команда `ПУСК` (адрес 140000) в популярных книгах не описана вовсе.

> **Расхождение.** «Программирование на БК-0010-01» приводит команду запуска как латинскую
> `S` (`S`, `S12700`). По первоисточнику это русская `С` от «СТАРТ»; Ю. А. Зальцман
> использует именно `С` (пример `С120234 ВВОД`).

Полезно:

* `C120234` + «ВВОД» — выход из ПМ **в Бейсик без стирания ОЗУ** (сохраняется ранее
  загруженная Бейсик-программа; ключи клавиатуры — клавиши 1–9 и 0 по регистру «АР2» —
  при этом не сохраняются).
* Из ПМ в МСД — через тесты: `Т`, «ВВОД», `РУС`, `Т`, `С` (тоже без стирания ОЗУ).

ПМ значительно уступает МСД по набору директив и возможностям.

## 8.4. EMT-диспетчер

Адрес: **100112**. Полное дизассемблирование [✓ ПЗУ]:

```asm
100112  010546                  MOV     R5,-(SP)        ; сохранить R5
100114  016605 000002           MOV     2(SP),R5        ; адрес возврата (следующей команды)
100120  014505                  MOV     -(R5),R5        ; сама команда EMT
100122  042705 177400           BIC     #177400,R5      ; выделить младший байт — номер EMT
100126  016505 100000           MOV     100000(R5),R5   ; адрес обработчика из таблицы
100132  004715                  JSR     PC,@R5          ; вызвать обработчик
100134  012605                  MOV     (SP)+,R5        ; восстановить R5
100136  000002                  RTI                     ; возврат из прерывания
```

**Таблица адресов обработчиков расположена прямо в начале ПЗУ**: адрес обработчика
`EMT n` лежит в слове по адресу **100000 + n**.

Смысл `EMT` — экономия памяти: обращение к подпрограмме командой `JSR PC,адрес` занимает
два слова, `EMT n` — одно. При сотнях обращений экономия достигает сотен слов, что для
машины с 16 К ОЗУ пользователя существенно.

На БК-0010 используются **только чётные номера EMT** — так проще диспетчер.

## 8.5. Описание EMT-функций

Общие соглашения: параметры передаются в РОН **до** вызова; после выполнения содержимое
РОН может измениться. Ниже отмечено, какие регистры не сохраняются.

> **Общее правило [РСП § 5.2]:**
> *при обработке программных запросов содержимое РОН R0–R5, за исключением особо указанных
> случаев, не меняется.* То есть по умолчанию EMT-функция сохраняет все регистры;
> исключения оговорены явно (`EMT 4` и `EMT 12` не сохраняют R0, `EMT 14` не сохраняет
> R0–R4).

### `EMT 4` — инициализация драйвера клавиатуры

Переписывает векторы 60 и 274 в исходные значения, сбрасывает маску прерываний от
клавиатуры (разряд 06 регистра 177660), устанавливает режим передачи кодов по запросам
рабочей программы и код 12 для клавиши «ВВОД».

**R0 не сохраняется.** Время ≈0,2 мс.

Применяется редко — например, если программа запретила прерывание от клавиатуры и его
нужно разрешить.

---

### `EMT 6` — ввод кода символа с клавиатуры

Работа программы приостанавливается до нажатия клавиши. Код нажатой клавиши заносится
в **младший байт R0**, старший байт очищается.

Применяется и для ввода, и просто для организации паузы.

> **Осторожно со стеком.** Пока машина ждёт нажатия по `EMT 6`, она находится
> в состоянии прерывания, то есть вершина стека уже на 4 меньше исходной. Нажатие «СТОП»
> в этот момент — не то же самое, что останов работающей программы, с точки зрения
> содержимого стека и значения SP.

Приём: командой `CLRB @#105` можно «отменить» предыдущее нажатие клавиши, тогда
следующий `EMT 6` гарантированно будет ждать нового нажатия.

### `EMT 10` — ввод строки символов с клавиатуры

| Вход | |
| --- | --- |
| `R1` | Адрес начала области ОЗУ для ввода |
| `R2` (мл. байт) | Максимальная длина строки в байтах (0 соответствует 200000 байт) |
| `R2` (ст. байт) | Код символа-ограничителя |

| Выход | |
| --- | --- |
| `R1` | Адрес байта, следующего за концом строки |
| `R2` | Разность заданной длины и реально введённого количества символов |

Ввод заканчивается по достижении заданной длины **либо** по вводу символа-ограничителя,
причём код ограничителя **заносится в строку последним**. Ошибки исправляются клавишей
«ЗАБОЙ» (код 30).

```asm
        MOV     #2000,R1        ; строка с адреса 2000
        MOV     #5100,R2        ; макс. длина 100 байт (64д),
                                ; ограничитель — код 12 («ВВОД») в старшем байте
        EMT     10
        TST     R2              ; до конца ли введена строка?
        BEQ     M
        DEC     R1              ; убрать код 12 из введённой строки
        INC     R2
C:      MOVB    #40,(R1)+       ; и дополнить остаток пробелами
        SOB     R2,C
M:      ...
```

### `EMT 12` — установка ключей клавиатуры

Программируемые ключи — клавиши `0`…`9`, нажатые в регистре «АР2» («НР»); каждая выдаёт
заданную текстовую строку.

| Вход | |
| --- | --- |
| `R0` | Номер ключа: **1 для клавиши «1» … 12 (=10д) для клавиши «0»** |
| `R1` | Адрес текста ключа; `R1 = 0` — сброс ключа |

**Первый байт текста должен содержать длину строки в байтах** и как символ не выводится.

**R0 не сохраняется.**

Если ключи программируются для языка высокого уровня, тексты нужно размещать в специально
отведённой зоне: для **Фокала — 1000…1377**.

```asm
        MOV     #TEX,R1
        MOVB    #7,(R1)+        ; число символов текста
        MOVB    'К',(R1)+
        MOV     'EY',(R1)+      ; «KEY N 5»
        MOV     ' N',(R1)+
        MOV     ' 5',(R1)+
        MOV     #5,R0           ; номер ключа
        MOV     #TEX,R1
        EMT     12
0:      BR      0
TEX:    END
```

Если ключ не запрограммирован, реакция на нажатие клавиш отсутствует.

> **Расхождение разрешено.** «Программирование на БК-0010-01» утверждало, что текст ключа
> должен заканчиваться нулевым байтом. **[РСП § 7.3.4]** говорит прямо:
> «R1 — адрес текста ключа (**первый байт — длина текста**)». Прав Ю. А. Зальцман;
> это же подтверждает назначение ячейки 122 («счётчик ключа» = длина текста текущего ключа).

### `EMT 14` — инициализация всех драйверов

Приводит БК практически в состояние после включения питания:

* ячейки 0…36 (векторы) := 100000, затем вектор 4 := 100442, вектор 30 := 100112,
  ячейка 32 := 200;
* ячейки 40…277 очищаются;
* выполняется `EMT 4`;
* инициализируется дисплей, экран очищается, устанавливаются исходные режимы;
* инициализируется ТЛГ-канал (`EMT 40`);
* порт вывода 177714 очищается;
* в 177716 записывается 220 (ТЛГ = 1, двигатель МЛ — стоп);
* приоритет процессора сбрасывается в 0.

**Содержимое R0–R4 не сохраняется** (R5 сохраняет сам EMT-диспетчер).
Время ≈240 мс — самая долгая EMT-функция.

> **Стек в исходное состояние не устанавливается** — прямо оговорено в **[РСП § 8.3.1]**. Поэтому по окончании работы программы возможен неожиданный эффект —
> выход из МСД в ПМ или даже в Фокал со стиранием ОЗУ.

Обратиться к этой функции можно и напрямую: `JSR PC,@#100140`.

> ⚠ **Ошибка в источнике.** В примечании редакции к книге Зальцмана для этого предлагается
> `JSR PC,@#100742`. По таблице обработчиков в ПЗУ **100742 — это обработчик `EMT 4`**,
> а `EMT 14` обслуживает **100140**. См. [01-источники-и-соглашения.md](01-источники-и-соглашения.md).

### `EMT 16` — передача кодов драйверу дисплея

Самая употребительная функция. Выводит на экран символ, код которого находится
в **младшем байте R0**, либо исполняет команду управления режимами экрана, если в R0 её код.

Содержимое старшего байта R0 значения не имеет и не меняется. **Все регистры сохраняются.**

Коды символов и командные коды — см. [09-экран-и-клавиатура.md](09-экран-и-клавиатура.md).

```asm
; 1) вывод символа «?»
        MOVB    #77,R0
        EMT     16

; 2) сброс экрана и вывод «А»
        MOVB    #14,R0
        EMT     16
        MOVB    'A',R0
        EMT     16

; 3) вывод двух символов одной константой
        MOV     'АБ',R0
        EMT     16
        SWAB    R0
        EMT     16

; 4) эхо клавиатуры до нажатия «ПРОБЕЛ»
0:      EMT     6
        EMT     16
        CMPB    #40,R0
        BNE     0

; 5) 64д звуковых щелчков
        MOV     #7,R0
        MOV     #100,R1
0:      EMT     16
        SOB     R1,0

; 6) вывод строки посимвольно до нулевого байта
0:      EMT     6                   ; пауза
        MOV     #TEX,R1
        MOVB    #14,(R1)+           ; команда очистки экрана
        MOVB    'П',(R1)+
        MOV     'ри',(R1)+
        MOV     'ве',(R1)+
        MOVB    'т',(R1)+
        CLRB    (R1)+               ; нулевой байт — конец текста
        MOV     #TEX,R1
1:      MOVB    (R1)+,R0
        BEQ     0
        EMT     16
        BR      1
TEX:    END
```

### `EMT 20` — вывод строки символов на экран

Действие, обратное `EMT 10`.

| Вход | |
| --- | --- |
| `R1` | Адрес начала строки |
| `R2` (мл. байт) | Длина строки (0 соответствует 200000) |
| `R2` (ст. байт) | Код символа-ограничителя; **выводится на экран последним** |

Строка может содержать не только символы, но и командные коды — очистку экрана,
переключение 32/64, смену цвета и т. п.

```asm
0:      MOV     #TEX,R1         ; ввод строки (макс. длина 377 = 255д байт,
        MOV     #5377,R2        ; ограничитель — код 12 «ВВОД»)
        EMT     10
        MOV     #TEX,R1         ; и её вывод
        MOV     #5377,R2
        EMT     20
        BR      0
TEX:    END
```

**Важно для драйверов:** вильнюсский Бейсик выдаёт весь свой текст (всё, кроме сообщения
«Ок.») именно через `EMT 20`, а не через `EMT 16`.

### `EMT 22` — вывод символа в служебную строку

| Вход | |
| --- | --- |
| `R0` | Код символа; **R0 = 0 — очистка служебной строки** |
| `R1` | Номер позиции в служебной строке (отсчёт от левого края, первый символ — 0) |

Выводится **по одному символу** — для строки нужен цикл. Символы отображаются как в режиме
БЛР-ИСУ: коды управления (10, 22, 30 и т. п.) показываются стрелками.

В правой части служебной строки машина сама выводит индикаторы режимов, поэтому
пользовательский текст там может быть затёрт.

```asm
0:      MOV     #2,R1               ; вывод с 3-й позиции
        EMT     6                   ; пауза
        MOV     #TEX,R2
        MOV     #233,R0             ; команда переключения формата
        EMT     16
        CLR     R0                  ; очистка
        EMT     22                  ; служебной строки
        MOV     'Пр',(R2)+
        MOV     'ив',(R2)+
        MOV     'ет',(R2)+
        MOV     '! ',(R2)+
        CLRB    (R2)+
        MOV     #TEX,R2
1:      MOVB    (R2)+,R0
        BEQ     0
        EMT     22
        INC     R1
        BR      1
TEX:    END
```

Альтернативный способ вывода в служебную строку — через ячейку `160` (адрес текущего
символа):

```asm
        MOV     @#204,@#160     ; база видеопамяти
        ADD     #36100,@#160    ; + смещение служебной строки
        MOV     #TXT,R1
        CLR     R2
        EMT     20
```
На Бейсике: `POKE &O160,PEEK(&O204)+&O36100 : ?"текст"` (работает только в программе,
не в непосредственном режиме).

### `EMT 24` — установка курсора по координатам

| Вход | |
| --- | --- |
| `R1` | Координата X |
| `R2` | Координата Y |

Работает и в символьном, и в графическом режиме (в графическом устанавливается графический
курсор). Начало координат — левый верхний угол экрана.

Если координата превышает число знакомест (точек), курсор устанавливается **по модулю**:
при X = 79 и ширине 64 символа курсор встанет в позицию 79 mod 64 = 15.

---

### `EMT 26` — чтение координат курсора

Возвращает X в `R1`, Y в `R2`. Работает в обоих режимах.

### `EMT 30` — формирование точки по координатам

| Вход | |
| --- | --- |
| `R0` | Код операции: **1 (или любое ненулевое) — запись, 0 — стирание** |
| `R1` | X |
| `R2` | Y |

Предварительная установка графического режима не требуется — команда работает и в символьном
режиме, и в режиме текстовой графики. Цвет задаётся заранее (командой через `EMT 16`
или записью маски в ячейку 214).

Пределы координат [РСП § 8.3.7]: **максимум Y = 239д**; максимум X зависит
от режима — **511д** в режиме «64 символа в строке» и **255д** в режиме «32 символа».
Значениям (0, 0) соответствует верхняя левая точка **информационного** поля экрана.

Если координаты выходят за пределы экрана, команда игнорируется, но **заданные координаты
запоминаются** как последние отработанные (в ячейках 176 и 200).

### `EMT 32` — формирование вектора

Параметры те же, что у `EMT 30`; задаются координаты **конца** вектора. Началом считается
конец последнего вектора (`EMT 32`) либо последняя обработанная точка (`EMT 30`).

Если начало или конец вектора выходят за экран, вектор всё равно строится, но отображается
только видимая часть.

```asm
; «муаровый» узор
        MOV     #1,R0               ; зачерчивание экрана
        CLR     R3                  ; из левого верхнего угла
0:      CLR     R1                  ; фигурой типа «радиальный луч»
        CLR     R2
        EMT     30
        MOV     R3,R1               ; R3 — буфер координаты X конца луча
        MOV     #357,R2
        EMT     32
        CMP     (R3)+,(R3)+         ; R3 += 4 одним словом
        BR      0
```

Пример с явным заданием цвета:

```asm
        EMT     14                  ; привести экран в исходное состояние
        MOV     #233,R0             ; режим «32 символа в строке»
        EMT     16
        MOV     #1,R0               ; точка текущим (красным) цветом
        CLR     R1
        CLR     R2
        EMT     30
        MOV     #125252,@#214       ; код зелёного цвета в ячейку маски
        MOV     #111,R1
        MOV     R1,R2
        EMT     32                  ; зелёный вектор из (0,0) в (111,111)
```

### `EMT 34` — чтение слова состояния дисплея (ССД)

Возвращает в `R0` слово, каждый разряд которого — индикатор режима дисплея
(1 — включён, 0 — выключен).

ССД собирается из массива служебных байтов в системной области начиная с адреса 40:
каждому биту ССД соответствует байт, содержащий 0 или 377 (исключение — разряд 03,
регистр «РУС», которому соответствует значение **200** в ячейке 43).

#### Таблица слова состояния дисплея

| Разряд ССД | Адрес байта | Включённый режим |
| --- | --- | --- |
| 00 | 40 | Цвет / режим «32 символа в строке» |
| 01 | 41 | Инверсия экрана |
| 02 | 42 | Режим «РП» (расширенной памяти) |
| 03 | 43 | Регистр «РУС» (значение 200) |
| 04 | 44 | Подчёркивание символа |
| 05 | 45 | Инверсия символа |
| 06 | 46 | Индикация символов управления («ИСУ») |
| 07 | 47 | Блокировка редактирования («БЛР») |
| 08 | 50 | Режим текстовой графики «ГРАФ» |
| 09 | 51 | Режим «ЗАП» (запись точек) |
| 10 | 52 | Режим «СТИР» (стирание точек) |
| 11 | 53 | Режим «32 символа» в служебной строке |
| 12 | 54 | Подчёркивание в служебной строке |
| 13 | 55 | Инверсия символа в служебной строке |
| 14 | 56 | Гашение курсора |
| 15 | 57 | Не используется |

Прямая запись в эти байты позволяет переключать режимы **на несколько порядков быстрее**,
чем командами через `EMT 16`, но с оговорками — см. [07-системная-область.md](07-системная-область.md).

### `EMT 36` — работа с магнитофоном

Самое сложное командное прерывание БК. Подробно описано в
[10-магнитофон.md](10-магнитофон.md).

Кратко: в `R1` заносится адрес **блока параметров** (обычно 320); байт «команда» задаёт
операцию (0 — стоп двигателя, 1 — пуск, 2 — запись, 3 — чтение, 4 — фиктивное чтение),
байт «ответ» возвращает результат.

### `EMT 40` … `EMT 50` — последовательный (телеграфный) канал

| EMT | Функция | Вход / выход |
| --- | --- | --- |
| `40` | Инициализация драйвера, установка скорости | вход: `R0` — номер скорости (0 → 9600 … 10 → 50 бод) |
| `42` | Передача байта на линию | вход: `R0` — младший байт |
| `44` | Приём байта с линии | выход: `R0` — младший байт |
| `46` | Передача массива по линии | вход: `R1` — адрес, `R2` — длина; выход: `R1` — за концом, `R2` = 0 |
| `50` | Приём массива с линии | вход: `R1` — адрес, `R2` — длина; выход: `R1` — за концом |

Драйвер требует доработки машины (перемычки 52 и 53). Подробное описание —
протокол, таблица скоростей, приём с прерываемым ожиданием, загрузка по линии —
в отдельной главе [11-последовательный-канал.md](11-последовательный-канал.md).

## 8.7. Тест-система

**Приглашение: `+`**

Вход:

* после включения (БК-0010-01 требует подключённого блока МСТД): нажать `ЛАТ`, `ЗАГЛ`,
  затем `Р`, `ПРОБЕЛ`, `Т`, `ВВОД`;
* из Фокала — `P T`;
* из ПМ — команда `T`;
* адрес запуска — `160100`.

Тесты запускаются цифровыми клавишами **1…5**:

| Тест | Что проверяет |
| --- | --- |
| 1 | ОЗУ и ПЗУ (контрольные суммы) |
| 2 | Клавиатура (рассчитан на клавиатуру БК-0010) |
| 3 | Порт ввода-вывода |
| 4 | Знакогенератор |
| 5 | Магнитофон |

Набор из пяти тестов проверяет все системы машины, хотя алгоритмы некоторых тестов
довольно примитивны.

Выход из тест-системы в Фокал — клавиша `К`.
Переход в МСД (пультовый отладчик) — включить русский шрифт клавишей `РУС` и набрать `ТС`.

## 8.8. МСД — мониторная система диагностики (пультовый отладчик)

**Приглашение: `¤`** («знак денежной единицы», на жаргоне — «колесо», «черепашка», «солнышко»)

Вход: из тест-системы — `РУС`, `Т`, `С`.

Все числа МСД принимает и выводит **только в восьмеричной системе**, максимум шесть цифр
(при большем числе действительны последние шесть). Незначащие нули слева можно не набирать.
Исправление — клавиша «ЗАБОЙ» (код 30).

Буквенные директивы набираются **в регистре РУС-ЗАГЛ**, единственное исключение —
директива `G`, которая набирается в регистре ЛАТ-ЗАГЛ.

Обозначение `(...)` ниже — восьмеричное число, набираемое **перед** буквой директивы.
Буква без числа обычно означает «индицировать», буква с числом — «установить».

### Директивы работы с адресом и длиной

| Директива | Действие |
| --- | --- |
| `(...)А` | Установить текущий адрес A |
| `А` | Проконтролировать текущий адрес; ответ вида `А=001000` |
| `(...)Д` | Установить длину массива Д (в байтах) |
| `Д` | Проконтролировать длину массива |

### Директивы работы с памятью

| Директива | Действие |
| --- | --- |
| `И` | Индикация слова по текущему адресу |
| `(...)И` | Запись слова по текущему адресу |
| `Б` | Индикация байта по текущему адресу |
| `(...)Б` | Запись байта по текущему адресу |
| `,` | Чтение слова **с инкрементом**: A += 2, затем вывод слова |
| `(...),` | Запись слова по A, затем A += 2 и вывод слова |
| `-` | Чтение слова **с декрементом**: A -= 2 |
| `(...)-` | Запись слова по A с декрементом |
| `.` / `:` | Чтение байта с инкрементом / с декрементом (A ± 1) — **см. предупреждение ниже** |
| `(...).` / `(...):` | Запись байта с инкрементом / с декрементом |
| `Ц` | **Циклическое** (непрерывное) чтение слова по адресу A. Выход — «СТОП» |
| `Щ` | **Снять защиту системной области** (адреса 0…777). Восстановление защиты — «СТОП» |

> ⚠ **Неразрешённое расхождение по байтовым директивам.** Заводское «Руководство
> системного программиста» [РСП, Прил. 2, табл. 5] назначает `:` — байт **с инкрементом**,
> `.` — байт **с декрементом**. Обе популярные книги (Зальцман; «Программирование
> на БК-0010-01») утверждают обратное: `.` — инкремент, `:` — декремент.
> В таблице символов директив, извлечённой из ПЗУ МСТД (адрес `173654`), коды `.` (056)
> и `:` (072) стоят рядом, как и пара `,` (054) / `-` (055), где порядок
> «инкремент, декремент» известен достоверно, — это косвенно говорит в пользу версии
> популярных книг. **Достоверно вопрос не разрешён**: проверьте на реальной машине или
> в эмуляторе, прежде чем полагаться на конкретный символ.

Слово и байт всегда выводятся шестью цифрами; при выводе байта три старшие цифры — нули.
При вводе байта запись производится по модулю 256д. При байтовых операциях адрес A может
быть нечётным — тогда он адресует старший байт слова с чётным адресом на 1 меньше.

Приостановить вывод на экран в МСД — `СУ/@`, повторный пуск — любая клавиша или снова `СУ/@`.

### Директивы работы с массивами

| Директива | Действие |
| --- | --- |
| `(...)Р` | **Размножить** число `(...)` во все слова диапазона A … A+Д (не включая последнее) |
| `Х` | **Контрольная сумма** массива A длиной Д; ответ `=(...)` |
| `(...)П` | **Переписать** (скопировать) массив A длиной Д по адресу `(...)` |
| `(...)С` | **Сравнить** эталонный массив A длиной Д с массивом по адресу `(...)` |
| `(...)Л` | **Листать**: вывести на экран `(...)` байт начиная с адреса A, по словам. После этого A := A + (...) |

Так как запись производится по словам, а A и Д задаются в байтах, следует задавать
чётные A и Д — иначе используется ближайшее меньшее чётное значение.

Контрольная сумма МСД (директива `Х`) — циклическая: сложение всех слов массива
с прибавлением бита переноса за пределы слова.

Расхождения по директиве `С` выводятся в виде:

```
     (эталонный массив)      (контролируемый массив)
(1)  адрес:      данные      адрес:      данные
(2)  адрес:      данные      адрес:      данные
```

Если массивы совпадают, на экран ничего не выводится.

**Пересылка с пересечением зон**: `2000А10000Д1000П` работает, а `1000А10000Д2000П`
(«в обратную сторону») испортит оба массива — пересылка идёт по словам от начала массива.

### Директивы работы с магнитофоном

| Директива | Действие |
| --- | --- |
| `МП` | **Пуск** двигателя магнитофона (при наличии ДУ) |
| `МС` | **Останов** двигателя магнитофона |
| `МФ` | **Фиктивное чтение** («поиск файла»): на запрос `ИМЯ=` вводится имя файла, после которого магнитофон остановится. Загрузка и проверка КС не производятся; несовпадающие имена выводятся на экран. Используется для просмотра содержимого кассеты |
| `МЧ` | **Чтение файла**. Запросы: `АДРЕС=` (0 — грузить по адресу из оглавления файла), `ИМЯ=` |
| `МЗ` | **Запись файла**. Запросы: `АДРЕС=`, `ДЛИНА=` (в байтах), `ИМЯ=` (до 16д символов, дополняется пробелами) |

При исполнении `МФ`, `МЧ`, `МЗ` двигатель включается и выключается автоматически через ДУ.

> **По поводу директивы `МС`.** Ю. А. Зальцман называет её бессмысленной («по нажатию
> первой же клавиши `М` магнитофон остановится»). Заводское руководство поясняет иначе:
> пара `МП`/`МС` служит **для подмотки магнитной ленты** — при подключённом ДУ иначе
> невозможно даже перемотать ленту с клавиш магнитофона.

### Директивы управления

| Директива | Действие |
| --- | --- |
| `(...)G` | **Запуск программы** с адреса `(...)`. Единственная директива в регистре ЛАТ-ЗАГЛ. Возврат в МСД — клавишей «СТОП» либо передачей управления по адресу **160100** |
| `К` | Выход из МСД: управление передаётся Фокалу (адрес 120000). **ОЗУ пользователя стирается**, кроме зоны 1000…1377 |
| `ТК` | Выход в тест-систему (приглашение `+`). Если не проводить тесты 1 и 5, содержимое ОЗУ сохраняется. Обратно в МСД — `РУС`, `Т`, `С` |
| `ТД` | Переход к тестам внешней диагностики (нужна дополнительная аппаратура на разъёме МПИ) |
| `Т0`…`Т5` | Запуск тестов МСД. Отличаются от тестов 1…5 тест-системы. Полезен тест 2; тест 0 выполняется только в составе локальной сети (класс КУВТ) |

### Диагностические сообщения МСД

| Сообщение | Значение |
| --- | --- |
| `ЗЩ` | **Защита**: попытка записи в системную область 0…777 директивой МСД. Снимается директивой `Щ`. Запрет действует только для директив МСД — от программы пользователя системная область не защищена |
| `ЗВ(адрес)` | **Зависание**: запись по адресу ПЗУ либо чтение/запись по несуществующему адресу. Прерывание по вектору 4 |
| `НК` | **Неправильная команда**: код, отсутствующий в наборе команд ЦП. Прерывание по вектору 10 |

Эти сообщения выдаются только при выполнении программ, загруженных и запущенных **в МСД**,
либо при выполнении самих директив МСД. Если загрузка и запуск шли из ПМ, либо программа
пользователя изменила векторы 4 и 10, сообщений не будет.

### Практические приёмы работы в МСД

**Ввод и запуск программы в кодах.** Например, сброс экрана и вывод «А»:

```
1000А
12700, 14, 104016, 12700, 101, 104016, 0,
1000G
```

(на выводимые по директиве `,` числа внимания не обращать). При вводе программы в кодах
рекомендуется вводить её **дважды по разным адресам** и затем сверять директивой `С` —
маловероятно, что обе копии будут набраны с одинаковыми ошибками.

**Параметры загруженного файла:**

| Ячейка | Что содержит |
| --- | --- |
| `264` | Адрес загрузки (фактический) |
| `266` | Длина массива |
| `312` | Контрольная сумма файла (вычисляется **иначе**, чем по директиве `Х`, и обычно не совпадает с ней) |
| `346` | «Истинный» адрес из оглавления на ленте |
| `350` | «Истинная» длина из оглавления |

Директива `264А4Л` покажет адрес и длину; `312АИ` — контрольную сумму.
Ячейки 346 и 350 заполняются и при фиктивном чтении (`МФ`), то есть параметры файла
можно узнать, не загружая его.

**Переход в ПМ без стирания экрана и без выхода из режима РП:**

```
4АЩ100442И
```
затем нажать «СТОП».

**Переход в Фокал без стирания ОЗУ:**

```
Щ
120020А26Д0П
262А177777И
«СТОП»
```

После этого Фокал выдаёт «ОСТАНОВ ПО КЛАВИШЕ СТОП». Условия успеха: выход из Фокала перед
этим должен быть сделан **непосредственно в МСД**, а не через ПМ, и в МСД не должны
загружаться (тем более запускаться) программы в кодах. При соблюдении этих условий
содержимое ОЗУ полностью сохраняется, Фокал-программы можно продолжать выполнять.

Программная реализация того же:

```asm
BEG:    CLR     R0                  ; адрес пересылки
        MOV     #120020,R1          ; адрес информации в ПЗУ Фокала
1:      MOV     (R1)+,(R0)+         ; пересылка блока длиной 26
        CMP     #120046,R1
        BGE     1
        MOV     #-1,@#262           ; признак кода «ВВОД»
        MOV     PC,R0               ; вычисление адреса начала блока
        ADD     (PC)+,R0            ; в перемещаемом
        .@BEG+2                     ; формате
        MOV     R0,@#1744           ; ограничить доступную Фокалу память
        HALT                        ; «СТОП» — выход в Фокал
```

**Проверка контрольной суммы ПЗУ МДС:** `100000А20000ДХ` → ответ `=177777`.
Это то же значение, которое БК выдаёт для первого ПЗУ в тесте 1.
[✓ Проверено расчётом по образу `bk10_017_mon.rom`: циклическая сумма слов = 177777,
байтовая сумма (та, что попадает в ячейку 312) = 017341.]

**Эффектная демонстрация:** `100000А20000Д40000П` — содержимое ПЗУ почти мгновенно
появляется на экране (перемещено более 4000д слов).

## 8.9. Системные (супервизорные) драйверы: перехват EMT

Ключевая идея: вместо того чтобы дорабатывать каждую программу пользователя (редактор,
Бейсик, Фокал), можно **перехватить вектор `@#30`** и «сесть» своим драйвером на
EMT-функции. Такой резидентный драйвер работает со всеми программами сразу.

Именно так реализованы:

* драйверы принтера (перехват `EMT 16` / `EMT 20`);
* работа с диском во всех дисковых ОС для БК (NORD, ANDOS и др.) — перехват `EMT 36`;
* универсальный драйвер SCREW ANIRAM-MIRIADA;
* нестандартные форматы записи на МЛ (например, 4000 бод вместо 1200);
* замена знакогенератора и векторной графики (`EMT 32`).

### Скелет драйвера принтера

```asm
; Инициализация драйвера
        MOV     PC,R0               ; вычислить адрес супервизора
        ADD     (PC)+,R0            ; в перемещаемом
        .@EMT+2                     ; формате
        MOV     R0,@#30             ; записать новый вектор @#30
        HALT
; Супервизорная программа
EMT:    MOV     R5,-(SP)            ; сохранить R5
        MOV     2(SP),R5            ; адрес следующей команды
        CMP     #104016,-(R5)       ; текущая команда — EMT 16?
        BNE     3                   ; нет — выход
        MOV     R0,-(SP)            ; сохранить R0
1:      BIT     #400,@#177714       ; принтер готов?
        BEQ     1                   ; нет — ждать
        BIS     #400,R0             ; строб-бит
        MOV     R0,@#177714         ; код символа и строб — в порт
2:      BIT     #400,@#177714       ; код принят?
        BNE     2                   ; нет — ждать
        BIC     #400,R0             ; очистить строб-бит
        MOV     R0,@#177714
        MOV     (SP)+,R0            ; восстановить R0
3:      MOV     (SP)+,R5            ; восстановить R5
        JMP     @#100112            ; выход в штатный EMT-диспетчер
```

Как опознаётся команда: адрес следующей команды лежит в стеке за 2 байта от вершины,
код предыдущей — в памяти за 2 байта до неё, отсюда `MOV 2(SP),R5` + `-(R5)`.

Протокол принтера: дождаться готовности (разряд 08 порта ввода), выставить строб-бит
(разряд 08 порта вывода) вместе с кодом символа, дождаться снятия готовности, снять строб.
Порт инвертирующий, поэтому для принтера с прямым кодом понадобится `COM R0`; кодовая
таблица принтера может потребовать перекодировки.

### Защита от `EMT 14`

Команда `EMT 14` в программе пользователя перепишет все векторы и «сбросит» драйвер.
Её надо перехватить и выполнить «под контролем»:

```asm
3:      CMP     #104014,@R5         ; текущая команда — EMT 14?
        BNE     4                   ; нет — выход в EMT-диспетчер
        MOV     @#30,-(SP)          ; сохранить свой вектор @#30 в стеке
        MOV     #100112,@#30        ; записать «нормальный» вектор
        EMT     14                  ; исполнить EMT 14
        MOV     (SP)+,@#30          ; восстановить свой вектор
        MOV     (SP)+,R5
        RTI                         ; выход из прерывания (в диспетчер уже нельзя!)
4:      MOV     (SP)+,R5
        JMP     @#100112
```

Приём работает потому, что `EMT 14` не трогает стек. Альтернатива — вызвать
функцию напрямую: `JSR PC,@#100140` (см. §7.6).

### Ключ включения/выключения печати

Ячейка-«переключатель» (например, `@#374` — «на самом дне» стека):

* при инициализации драйвера ячейка сбрасывается;
* символ выдаётся на печать только когда в ячейке не нуль;
* код каждого символа проверяется на «ключ»; при совпадении ячейка инвертируется.

Например, «ключ» — код 1 (`СУ/А`, на Бейсике `?CHR$(1)`, на Фокале `X FCHR(1)`).

### Работа драйвера с языками высокого уровня

* **Фокал** выводит через `EMT 16`. Чтобы драйвер уцелел, надо запретить Фокалу доступ
  к занятой драйвером памяти: записать адрес начала драйвера в ячейку `@#1744`
  (эта ячейка в Фокале отвечает за границу доступного интерпретатору ОЗУ). Адрес
  вычислять псевдооператором `.@`, чтобы не нарушить перемещаемость.
* **Бейсик** выводит всё, кроме «Ок.», через `EMT 20`, поэтому нужна **эмуляция `EMT 20`**:
  вывести строку на принтер, посимвольно выдать её на экран через `EMT 16` и привести
  `R1`/`R2` в такое состояние, как будто `EMT 20` отработала штатно.
  Специальный вход в Бейсик не нужен — драйвер можно запустить прямо из Бейсика:
  ```basic
  DEF USR=&O30000
  ? USR(A)
  ```

### Слабые места супервизорного драйвера

1. Драйвер может быть затёрт данными или кодом программы пользователя — машина зависнет.
2. Программа пользователя может переписать вектор `@#30` напрямую, минуя `EMT 14`.
   К счастью, таких программ немного.

### Перехват `EMT 36` — дисковые ОС и спецформаты МЛ

Драйвер выделяет `EMT 36`, читает **блок параметров** (адрес — в `R1`), анализирует
команду, адрес, длину и имя файла, выполняет операцию своими средствами, после чего
приводит системные ячейки, стек и регистры в состояние «как будто сработала штатная
`EMT 36`».

Практические выводы, важные при написании прикладных программ:

* **ввод-вывод файлов делать только через `EMT 36`**, а не прямым обращением к
  «магнитофонным» подпрограммам монитора — иначе программа не будет работать с диском;
* при адаптации многофайловых программ к диску подгрузку частей тоже делать через `EMT 36`,
  а не собственным загрузчиком, работающим с каталогом и секторами — такой загрузчик
  привяжет программу к одной ОС.

## 8.10. Пример: графическая копия экрана на принтер

Подпрограмма рассчитана на принтер МС-6312 (система команд близка к EPSON), копирует экран
горизонтально с удвоением по вертикали, формат перемещаемый.

Коды команд принтера:

* строка `К1` = `30, 33, 100, 7`:
  `30` — отмена строки (CAN); `33` — ESC; `100` — «@», инициализация принтера;
  `7` — признак конца командной последовательности.
* строка `К2` = `33, 63, 30, 12, 33, 113, 0, 2, 7`:
  `33` ESC; `63` — «3», выбор N/216д-дюймового межстрочного интервала; `30` — N = 24д;
  `12` — перевод строки (LF); `33` ESC; `113` — «K», графический режим одинарной плотности;
  `0, 2` — число точек в графической строке (0 + 256д×2 = 512д — формат экрана БК);
  `7` — конец последовательности.

```asm
; Подпрограмма графического копирования экрана

        ASLB    R0                  ; на 2 точки
        RORB    @R1                 ; очередная точка = 0?
```

`@#177664`); при выходе за 77777 адрес корректируется вычитанием 40000.
