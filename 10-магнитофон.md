# 10. Магнитофон: `EMT 36` и формат файла на ленте

> **Источники главы**
> * **[РСП § 9]** «Обмен с магнитной лентой» (с. 45–49) — нормативное описание `EMT 36`,
>   блока параметров и протокола поиска файла.
> * **[З]** «Операторы прерывания» (описание `EMT 36` и формата файла на МЛ),
>   «Системная область» (ячейки драйвера магнитофона 300…316),
>   «Концепция системных драйверов» (перехват `EMT 36`).
> * **[МПСС]** (вторичный) — параметры накопителя.
> * **[ЭМ]** `bkemu-QT/devemu/Tape.cpp` — длительности импульсов, структура файла.

Внешняя память БК-0010-01 — бытовой кассетный магнитофон (штатно — «Электроника 302»),
подключаемый через разъём «МАГНИТОФОН». Носитель — стандартная компакт-кассета типа **МК60**.

| Параметр | Значение |
| --- | --- |
| Скорость обмена | **1200 бод** |
| Метод записи | разновидность широтно-импульсной модуляции |
| Плотность записи | ≈25 бит/мм |
| Ёмкость кассеты МК60 | до 256 Кбайт (статья разработчиков, 1985) … до 500 Кбайт («Руководство системного программиста») |

Контроллер накопителя построен по принципу программно-аппаратного управления: аппаратно
реализованы лишь регистр временного хранения и схема преобразователей уровня, все основные
функции выполняются программой драйвера.

Всё взаимодействие идёт через командное прерывание **`EMT 36`** — самое сложное
из EMT-функций БК. Обработчик расположен в ПЗУ по адресу **116076** [✓ ПЗУ].

## 10.1. Вызов `EMT 36`

| Вход | |
| --- | --- |
| `R1` | **Адрес блока параметров** |

Блок параметров может располагаться с любого чётного адреса ОЗУ, но в системной области
под него зарезервирована зона **320…371**. Именно её используют Фокал, Бейсик, ПМ и МСД.

## 10.2. Блок параметров

| Смещение | Адрес (штатный) | Размер | Мнемоника DMBK | Содержимое |
| --- | --- | --- | --- | --- |
| 0 | **320** | байт | `KOM` | **Команда** |
| 1 | **321** | байт | `OTWET` | **Ответ** (код завершения) |
| 2 | **322** | слово | `ADRMAS` | Адрес массива на запись или чтение |
| 4 | **324** | слово | `DLMAS` | Длина массива на запись (при чтении нужно обнулять) |
| 6 | **326…345** | 20 (16д) байт | `IMMAS` | Имя массива на запись или чтение |
| 26 | **346** | слово | `ADRTM` | Адрес **текущего** массива |
| 30 | **350** | слово | `DLTMAS` | Длина текущего массива |
| 32 | **352…371** | 20 (16д) байт | `IMTMAS` | Имя текущего массива |

**Текущим** называется массив (файл), имя которого прочитано последним, независимо от
того, загружался ли он в ОЗУ. Поля 346/350/352 заполняются при любом чтении, включая
фиктивное, — это позволяет узнать параметры файла, не загружая его.

### Байт «команда» (320)

| Значение | Операция |
| --- | --- |
| 0 | Останов двигателя магнитофона |
| 1 | Пуск двигателя магнитофона |
| 2 | **Запись** файла на МЛ |
| 3 | **Чтение** файла с МЛ |
| 4 | **Фиктивное чтение** (поиск / просмотр кассеты) |

При командах 2, 3, 4 двигатель включается и выключается автоматически — отдельно
подавать 0 и 1 не требуется.

> Команды 0 и 1 нужны только при магнитофоне с дистанционным управлением: после завершения
> операции БК выключает двигатель, и ленту становится невозможно даже перемотать — ДУ
> блокирует запуск с клавиш магнитофона. Для ручной перемотки нужно либо отстыковать
> штекер ДУ, либо заранее предусмотреть в программе команды 1/0 (аналог директив
> `МП`/`МС` в МСТД).

### Байт «ответ» (321)

| Значение | Смысл |
| --- | --- |
| 0 | Операция завершена без ошибок |
| 1 | Имя файла на МЛ не совпадает с заданным |
| 2 | Ошибка контрольной суммы |
| 4 | Останов по клавише «СТОП» |

Ячейка `301` (`PROH`) дублирует байт ответа и является по отношению к нему **первичной**.

### Протокол поиска файла [РСП § 9]

При чтении (команда 3) драйвер сравнивает прочитанное с ленты имя с заданным. Если имена
**не совпали**, драйвер:

1. записывает в байт ответа значение 1;
2. возвращает управление вызвавшей программе;
3. **двигатель магнитофона при этом не останавливает**.

Благодаря этому программа может **повторно передать управление драйверу, не изменяя блок
параметров**, и поиск нужного файла продолжится с того же места ленты. Именно на этом
построены все каталогизаторы и загрузчики многофайловых программ.

Останов двигателя производится по завершении операции (успешном или по «СТОП»), а также
явной командой 0.

### После успешной загрузки

Адрес загрузки и длина массива записываются также в ячейки **264** и **266**.
Если при загрузке задать адрес 0, файл будет загружен по адресу, указанному в его
оглавлении на ленте.

Контрольная сумма файла помещается в ячейку **312**. Она вычисляется **не так**, как
контрольная сумма по директиве `Х` МСД, и обычно с ней не совпадает.

## 10.3. Пример: запись файла на МЛ

Диалоговая программа: спрашивает адрес, длину и имя, затем записывает файл.

```asm
; Запись файла на МЛ с помощью EMT 36
BEG:    MOV     #346,R3             ; конец имени файла
0:      MOVB    #40,-(R3)           ; очистка имени файла — пробелы
        CMP     #320,R3             ; во все байты
        BNE     0                   ; до R3 = 320
        MOV     #2,(R3)+            ; команда «запись»; R3 = 322
        MOV     'A=',R0             ; запрос «АДРЕС=»
        CALL    INP                 ; ввод адреса; R3 = 324
        MOV     'Д=',R0             ; запрос «ДЛИНА=»
        CALL    INP                 ; ввод длины; R3 = 326
        MOV     'И=',R0             ; запрос «ИМЯ=»
        EMT     16                  ; выдача
        SWAB    R0                  ; запроса
        EMT     16                  ; на экран
        MOV     #5020,R2            ; ограничители: «ВВОД» или длина 16д
        MOV     R3,R1               ; адрес имени — 326
        EMT     10                  ; ввод имени
        MOVB    #40,-(R1)           ; заменить код 12 на пробел
        MOV     #320,R1             ; адрес блока параметров
        EMT     36                  ; выполнить запись файла
        EMT     6                   ; ожидание нажатия клавиши
        BR      BEG

; Выдача запроса и ввод числовых данных
INP:    EMT     16                  ; первый символ запроса
        SWAB    R0
        EMT     16                  ; второй символ
        CALL    @#100472            ; п/п ПЗУ: ввод восьмеричного числа в R5
        MOV     R5,(R3)+            ; число — в блок параметров
        MOV     #12,R0              ; перевод
        EMT     16                  ; строки
        RET
        END
```

Использована подпрограмма ПЗУ **`@#100472`** — ввод восьмеричного числа с клавиатуры
с возвратом результата в `R5` [✓ ПЗУ]. Это избавляет от размещения аналогичной довольно
длинной подпрограммы в ОЗУ.

## 10.4. Формат файла на магнитной ленте

Структура записи:

```
┌──────────────────────────────┐
│ Установочная последователь-  │  10000 нулевых битов
│ ность (УсП)                  │
├──────────────────────────────┤
│ Маркер                       │  специальная кодовая последовательность импульсов
├──────────────────────────────┤
│ Оглавление файла             │  точная копия блока 322…345:
│                              │  адрес (сл.), длина (сл.), имя (20 байт)
├──────────────────────────────┤
│ Тело файла                   │
├──────────────────────────────┤
│ Контрольная сумма            │  последнее слово
└──────────────────────────────┘
```

### Установочная последовательность

10000 нулевых битов. Служит для двух целей:

1. поиск начала файла;
2. **автоматическая подстройка скорости чтения** — для разных БК и особенно разных
   магнитофонов она может существенно различаться. Это же свойство позволяет записывать
   файлы с повышенной скоростью.

Результат вычислений по УсП заносится в ячейку `314` (`GRDL0`) — «константа сравнения»,
позволяющая отличать нулевой бит от единичного.

### Маркер

Последовательность из 10000 нулей может встретиться и внутри самого файла, поэтому вслед
за УсП записывается маркер. Он служит для:

* однозначного опознавания начала файла;
* определения **фазы записи** — полярность выхода разных магнитофонов может отличаться.
  Результат фиксируется в ячейке `300`: 0 — прямой сигнал, 377 — инверсный.

Длительности импульсов (по реализации в `bkemu-QT/devemu/Tape.cpp`, где L — длина среднего
импульса):

| Длительность | Смысл |
| --- | --- |
| L | «0» и синхроимпульс |
| 2L | «1» |
| 4L | маркер |

### Оглавление и чтение

При **записи** оглавление — точная копия блока по адресам 322…345 (адрес, длина, имя).
При **чтении** прочитанные параметры заносятся по адресам 346…371.

После чтения оглавления производится сверка имени. При несовпадении в ячейку 301
записывается байт ответа 1 и происходит выход в основную программу. Если имя совпало —
выполняется истинное либо фиктивное чтение в зависимости от команды.

### Контрольная сумма

* КС, сопровождающая файл на ленте, вычисляется как **сумма всех байтов файла с учётом
  битов переноса**.
* При вычислении КС загруженного массива **не учитываются** УсП, маркер, оглавление
  и сама КС.
* Прочитанная и вычисленная КС сравниваются; результат формирует байт ответа.

> Известный дефект: иногда БК воспринимает все считываемые биты как нулевые, включая
> записанное значение контрольной суммы. Ошибка чтения очевидна визуально, но компьютер
> считает операцию выполненной правильно (КС пустого массива всегда равна нулю независимо
> от длины).

## 10.4а. Формат файла `.bin`

Файл `.bin` — де-факто стандарт хранения БК-программ на современных носителях и в
эмуляторах. Он представляет собой **оглавление файла с ленты плюс тело**, без УсП,
маркера и контрольной суммы:

```
слово 0 (байты 0–1) — адрес загрузки
слово 1 (байты 2–3) — длина массива в байтах
далее               — тело файла (<длина> байт)
```

Формат порождён форматом оглавления на МЛ (§9.4) и потому напрямую совместим
с загрузкой через `EMT 36`.

Подтверждение — документация кросс-ассемблера БКТурбо8
(`GID-src/BKemu/Docs/BKTurbo8.html`): «Генерируется `.bin` файл, у которого первым словом
идёт адрес загрузки, вторым — размер файла, совместимый с эмуляторами». Там же упомянут
вариант `.raw` — то же тело без заголовка.

Максимальная длина получаемой программы в БКТурбо8 — `0177000` байт.

## 10.5. Имя файла

До **16д (20 восьм.) любых символов**. Если имя короче, оно автоматически дополняется
пробелами (код 40). При вводе имени через `EMT 10` с ограничителем «ВВОД» последний
введённый байт (код 12) нужно заменить пробелом — см. пример выше.

## 10.6. Магнитофон и дисковые ОС

Практически во всех дисковых ОС для БК (NORD, ANDOS и др.) реализована **автоматическая
переадресация чтения-записи по `EMT 36` на диск**: EMT-прерывание перехватывается,
и функция `EMT 36` подменяется её «дисковой» версией. Это обеспечивает работу с диском
большинства старых программ, рассчитанных на магнитофон.

Два важных практических вывода:

1. **Ввод-вывод файлов в прикладных программах нужно делать стандартным способом —
   через `EMT 36`**, а не прямым обращением к «магнитофонным» подпрограммам монитора
   (кроме особых случаев, когда программа рассчитана только на магнитную ленту).
2. При адаптации многофайловых программ к диску подгрузку частей тоже следует делать
   **только через `EMT 36`**. Попытки писать собственные загрузчики, работающие
   напрямую с каталогом имён и секторами, приводят к тому, что программа работает
   лишь в одной ОС, и кому-то придётся «взламывать» её и делать адаптацию заново.

Тем же путём — перехватом `EMT 36` — реализуются нестандартные форматы записи на МЛ.
Автор книги описывает драйвер, работающий на **4000 бод** вместо стандартных 1200,
совместимый со всеми программами, которые пользуются штатным `EMT 36`.

Аналогично можно организовать обмен с квазидиском на дополнительном ОЗУ и даже вывод
на принтер тех блоков, которые программа собиралась записать на ленту.

## 10.7. Инструменты в этом архиве

Для подготовки WAV-файлов, воспроизводимых на реальный БК через магнитофонный вход,
в архиве есть три независимых конвертера `.bin` → `.wav`:

| Каталог | Реализация |
| --- | --- |
| `bin2wav/` | Node.js CLI (`npm install -g bin2wav-cli`); ключи `--input/--output/--model 11/--speed/--play` |
| `bkbin2wav/` | Python (`bkbin2wav.py`) и Go (`gobkbin2wav/`) |
| `bk-wav/`, `bkwav/` | Исходники на C: `bkbin2wav`, `bin2bk`, библиотека `wavlib/` |

Ключ `--model 11` в `bin2wav` даёт запись на 17 % быстрее, пригодную для БК-0011(М),
но несовместимую с БК-0010(-01).

Эмулятор `bkemu-QT` читает и пишет WAV-образы ленты напрямую
(`devemu/Tape.cpp`, окно «Магнитофон»).
