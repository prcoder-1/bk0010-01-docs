# 14.2. Накопитель на гибких магнитных дисках (НГМД)

> Документ каталога периферии — [../14-периферия.md](../14-периферия.md).
>
> **Источники**
> * **[З]** — доработка КНГМД для БК-0010-01.
> * **[ВП128]** — описание БМК 1801ВП1-128 из проекта восстановления схем серии 1801
>   (`1801BM1/k1801`): регистры, работа, цоколёвка.
> * **[326]** — комментированный дизассемблер прошивки КНГМД, К. В. Гаршенин, 1993.
> * **[Каз]** — переопределение разрядов `177130` в контроллерах СМК.
> * **[ПерифБК]** — тема форума zx-pk.ru «Список периферии к БК» (контроллер «Комкон»).
> * **[Схемы]** — интерфейс дисковода.

Штатный путь к дискете у БК — **контроллер НГМД (КНГМД)**, подключаемый к разъёму
МПИ. В нём три части, описанные ниже по порядку: сама плата и её подключение к БК
(§14.2.1), однокристальный контроллер **1801ВП1-128** с регистрами `177130`/`177132`
(§14.2.2) и драйвер в ПЗУ **326** с точками входа от `160000` (§14.2.4).

Те же регистры и тот же драйвер используют все совместимые контроллеры: **СМК /
«АльтПро»** ([../17-контроллер-СМК.md](../17-контроллер-СМК.md); они же добавляют
жёсткий диск, §17.12–17.14), а современные **Gryphon-MPI** и **AZБК** подставляют
вместо дискеты образ на карте памяти ([../18-Gryphon-MPI.md](../18-Gryphon-MPI.md),
§18.8; [../19-AZБК.md](../19-AZБК.md)).

## 14.2.1. Подключение КНГМД к БК

Для нормальной работы с БК-0010-01 КНГМД необходимо доработать: контакты **А29** и **А14**
разъёма МПИ соединить с шиной «+5 В» через резисторы 150…200 Ом. Этим достигается
отключение встроенного ПЗУ Бейсика при подключении КНГМД. Назначение этих
контактов — [разъёмы.md](разъёмы.md), §14.1.8.

Если в БК-0010-01 установлен переключатель для выборочного подключения ПЗУ Бейсика,
Фокала и тестов, доработка не требуется — достаточно перед подсоединением КНГМД
отключить все встроенные ПЗУ.

Для БК-0010 отключение ПЗУ по 23-му выводу микросхем — единственный способ.

В КНГМД есть дополнительный вывод шины МПИ (контакты под разъём на боковой стороне платы),
к которому можно подключать дополнительные устройства (например, блок энергонезависимого
ОЗУ). **Линия WTBT на дополнительные контакты не выведена** — если сигнал WTBT нужен,
его следует снимать непосредственно с вывода В11 разъёма МПИ КНГМД.

ПЗУ контроллера НГМД попадает в адреса начиная с 160000, поэтому доступны резервные входы
`EMT 52`…`EMT 110` (см. [../09-монитор.md](../09-монитор.md), §9.4).

## 14.2.2. Контроллер НГМД 1801ВП1-128: регистры и работа [ВП128]

Однокристальный контроллер накопителя на гибких магнитных дисках. Именно он стоит
в основе КНГМД и всех совместимых контроллеров БК, поэтому **адреса `177130`
и `177132` — не «недокументированные регистры СМК», а штатные регистры этой
микросхемы** (см. §14.2.3 ниже). Как те же самые разряды использует под управление
дополнительным ОЗУ контроллер СМК — в
[../17-контроллер-СМК.md](../17-контроллер-СМК.md), §17.5.

Со стороны дисковода интерфейс **стандартный**: БК, как и прочие машины линии
PDP-11, использует **Shugart, 34 контакта** (иногда упакованный в 40-контактный
разъём) [Схемы]. Именно поэтому к БК подходят обычные приводы для ПК и их
современные заменители.

1801ВП1-128 — та же матрица К1801ВП1, что и контроллеры дисплея (`-037`)
и клавиатуры (`-014`), см. [../15-схемотехника-и-доработки.md](../15-схемотехника-и-доработки.md),
§15.1. Это **последний широко известный номер серии, пошедший в массовое
производство**: 308 ячеек матрицы, 525 связей. До его появления БК сохраняли
программы только на магнитофон.

| Параметр | Значение |
| --- | --- |
| Метод записи | **МФМ** (модифицированная частотная модуляция) |
| Тактовая частота (вход CLC) | **4 МГц** |
| Битовая скорость | **250 кбит/с** |
| Формат дискет | форматирование по стандарту **IBM** |
| Полином CRC | G(x) = x⁰ + x⁵ + x¹² + x¹⁶ |
| Обмен по МПИ | **только словный**, разрядность регистров 16 бит |

По отношению к процессору контроллер — **пассивное устройство**. Микросхема
декодирует всего два адреса:

| Адрес | По записи | По чтению |
| --- | --- | --- |
| **`177130`** | Регистр управления | Регистр состояния |
| **`177132`** | Буферный регистр данных (16 бит) | То же |

> ⚠ **Микросхема не защёлкивает адрес обращения целиком** по срезу `nSYNC` —
> только результат его предварительного дешифрирования [k1801]. Отсюда
> требование к времени предустановки адреса на шине относительно среза `nSYNC`:
> дешифратор не может «досмотреть» уже снятый со входов адрес, ему важно застать
> его результат уже готовым к моменту среза.

### Регистр `177130` по записи — управление

| Разряд | Имя | Назначение |
| :-: | --- | --- |
| 0…3 | `DS0`…`DS3` | **Выбор накопителя** 0…3 |
| 4 | `MSW` | Включение двигателя накопителя |
| 5 | `HS` | Выбор поверхности диска |
| 6 | `DIR` | Направление шага головки |
| 7 | `ST` | **Шаг.** Запись единицы порождает импульс; отдельного триггера нет, поэтому **обнулять разряд повторной записью не нужно** |
| 8 | `GDR` | Признак «начало чтения» |
| 9 | `WM` | Признак «запись маркера» — пропуск синхроимпульсов |
| 10 | `REZ` | Резервный; на некоторых платах управляет предкомпенсацией записи |

### Регистр `177130` по чтению — состояние

| Разряд | Имя | Назначение |
| :-: | --- | --- |
| 0 | `TR0` | Признак «нулевая дорожка» |
| 1 | `RDY` | Накопитель готов к работе |
| 2 | `WPR` | Запрет записи (защита от записи) |
| 7 | `TR` | **Готовность регистра данных** — основной флаг обмена |
| 14 | `CRC` | При чтении — «прочлось без ошибок»; при записи — «записывается сумма CRC» |
| 15 | `IND` | Сигнал индекса с НГМД |

> Разряды `TR0`, `RDY` и (почти полностью) `IND` считываются прямо со входов
> микросхемы и **на её работу не влияют**: поиск маркера, чтение и запись они
> не прерывают. Высокий уровень на `WPR` запрещает запись.

### Флаг `TR` и жёсткое требование по времени

`TR` устанавливается:

* при **записи** — когда младший байт регистра данных переписался в сдвиговый регистр;
* при **чтении** — когда в регистре данных чтения сформировалось очередное слово.

Сбрасывается любым обращением к регистру данных `177132` (по чтению или по записи),
а также низким уровнем на `nINIT`.

> ⚠ **Слово преобразуется за 64 мкс** (при CLC = 4 МГц). С этим периодом процессор
> обязан по флагу `TR` прочитать или записать `177132`, иначе операция выполнится
> некорректно. Отсюда и требование к драйверу диска — плотный опросный цикл
> с запретом прерываний; сравните с магнитофонным обменом, где темп задаёт сам
> драйвер ([../12-магнитофон.md](../12-магнитофон.md), §12.4).

### Маркер, `WM` и `GDR`

* Микросхема распознаёт **только маркер `A1` (10100001) с пропущенным синхроимпульсом**.
  Обнаружение маркера запускает преобразование информации.
* Пропуск синхроимпульсов при записи задаётся разрядом **`WM`**.
* Запись «1» в **`GDR`** частично приводит микросхему в исходное состояние, а снятие
  разрешает поиск маркера. **Рекомендуемый приём:** записать «1», затем «0» в зоне
  нулей, которая обычно предшествует маркеру, — это принудительно синхронизирует
  схему со считываемыми данными.

> **Ловушка `GDR`.** Если `GDR` был установлен, а импульсы чтения с дисковода
> прекратились (например, вставлена неформатированная дискета), внутренний
> стробируемый `GDR` фиксируется в активном состоянии и удерживает схему
> синхронизации в сбросе — **запись становится невозможна** без подачи активного
> низкого `nINIT`.

### Известный дефект: фаза ФАПЧ и нераспознанный маркер

Авторы микросхемы не смогли обеспечить надёжное распознавание маркера. Схема ФАПЧ
подстраивает генератор на **удвоенную** частоту битового интервала, поэтому
результирующая битовая частота может иметь **две фазы**:

* если первыми идут нулевые биты (а перед маркером обычно записана преамбула
  из нескольких нулевых байт) — фаза верна и маркер распознаётся;
* если сначала попадётся несколько единичных бит — фаза повёрнута на 180°
  и **маркер не распознаётся**.

Подтверждено и моделированием, и экспериментально [ВП128]. Практический вывод:
преамбула из нулей перед маркером — не формальность, а условие работоспособности.

### Цоколёвка

| Выводы | Сигнал | Назначение |
| --- | --- | --- |
| 1–16 | `nAD0`…`nAD15` | Мультиплексированные адрес/данные МПИ |
| 17…19 | `nSYNC`, `nDIN`, `nDOUT` | Стробы МПИ |

| 24 | `IND` | Индексный сигнал с НГМД |
| 25–27 | `nD03`…`nD01` | Записываемые данные в разных фазах (для предкомпенсации записи) |

> показывает, что импульс появляется **только на одном** из них, поэтому
> элементы «И» в схемах многих контроллеров на ВП1-128 избыточны — достаточно
> одного сдвигового регистра.

## 14.2.3. Разряды `177130`, переопределённые в СМК

> **Внимание:** это поведение **контроллера**, а не самой БК. В заводской документации
> на БК этих адресов нет; в справочник включены потому, что встречаются в программах
> и объясняют «странности», которые легко принять за особенность машины.

Ранее этот раздел назывался «недокументированные регистры СМК». Формулировка была
неточной: **`177130` и `177132` — штатные регистры микросхемы 1801ВП1-128**, общие
для всех контроллеров НГМД БК (полное описание — в §14.2.2). Особенность СМК
не в самих регистрах, а в том, что плата **навешивает на них дополнительный смысл**:
в `177130` пишется номер страницы дополнительного ОЗУ и код режима работы, а разряды
выбора накопителя `DS2` и `DS3` получают побочные функции:

| Разряд `177130` | По микросхеме [ВП128] | Что добавляет СМК [Каз] |
| :-: | --- | --- |
| **2** | `DS2` — выбор накопителя 2 | Установленный бит **отключает `177130` и `177132` по чтению**, пока не будет сброшен. Наследие контроллеров **А16**; было нужно для работы **Бейсика на БК-0010** |
| **3** | `DS3` — выбор накопителя 3 | На БК-0010 **подключает ПЗУ Бейсика**. Работает на оригинальных **СМК-64**; на прототипе СМК-256 и **репликах СМК-512 не реализован** |

Отсюда и наблюдение, что «не все страницы СМК работают одинаково»: это не ошибка
контроллера, а унаследованное переопределение разрядов. Практическое следствие —
на СМК **нельзя свободно пользоваться четырьмя накопителями**: выбор устройств 2 и 3
задевает посторонние функции.

Полная побитовая карта `177130` в «памятной» трактовке, протокол переключения и
таблица режимов — в [../17-контроллер-СМК.md](../17-контроллер-СМК.md), §17.5–17.7.

## 14.2.4. Драйвер НГМД: прошивка ПЗУ 326 [326]

Драйвер размещён в ПЗУ **КР1801РЕ2-326** внутри самого контроллера и доступен, как
только контроллер подключён к машине. Попадает в адреса с `160000`
(см. [../09-монитор.md](../09-монитор.md), §9.4 о резервных входах `EMT`).

Источник — комментированный дизассемблер К. В. Гаршенина (Москва, 1993). Автор
разбирал прошивку, имея на руках лишь распределение ячеек из руководства для БК-0011:
заводского описания драйвера не публиковалось.

> **Сходимость с §14.2.2.** Приведённая в [326] побитовая карта регистра `177130`
> совпадает с описанием микросхемы 1801ВП1-128 **до разряда**, хотя получена совсем
> иначе: дизассемблированием прошивки в 1993 году против восстановления схемы
> кристалла по фотографиям слоёв в наши дни. Разряд 10, названный у [ВП128] `REZ`,
> в [326] описан по назначению — «переключение схемы прекоррекции».

### Точки входа

Все — через `JSR PC,@#адрес`. Первые шесть слов ПЗУ представляют собой таблицу
переходов, поэтому адреса устойчивы к смене редакции прошивки.

| Адрес | Функция |
| --- | --- |
| **`160000`** | Автоматическая загрузка |
| **`160002`** | Загрузка с выбранного привода (номер в `R0`) |
| **`160004`** | Чтение-запись по **номеру блока** |
| **`160006`** | Чтение-запись по **номеру сектора и дорожки** |
| **`160010`** | Инициализация рабочей области |
| **`160012`** | Форматирование дорожки |
| **`160016`** | **Эмулятор расширенной арифметики** (см. [../05-система-команд.md](../05-система-команд.md), §5.3) |

### Автозагрузка

Загрузиться можно и прямо из пускового монитора: **`СТОП` `С160000` `ВВОД`**.

Алгоритм: рабочая область инициализируется по базовому адресу `2000` с параметрами
для НГМД 6022; с привода читается **сектор 1 дорожки 0** в ОЗУ по адресу `1000`;
при успехе управление передаётся на `1000`, а в `R0` кладётся номер привода.
Попытка считается неудачной, если нет диска, привод не защёлкнут или неисправен,
диск не отформатирован, произошла ошибка чтения или отсутствует начальный загрузчик.
Прошивка **326** пробует приводы 0 и 1; выборочная загрузка из встроенных мониторов
БК невозможна.

| 55 | 1 | `TURNS` | | Число оборотов диска на операцию |
| 56 | 1 | `SECRET` | | Число повторных поисков сектора |
| 57 | 1 | `ERRNUM` | | Буфер номера ошибки |
| 60 | 2 | `MAXSEC` | `000012` | Число секторов на дорожке |
| 62 | 2 | `HOLTIN` | — | Время задержки после индекса |
| 64 | 2 | `SECLEN` | `000400` | **Длина сектора в словах** |

Поля `CSRW`, `TRKTAB`, `FLAGS` после инициализации **изменять нельзя**.
`TDOWN`, `TSTEP`, `TRKCOR`, `BRETRY`, `FLGTAB` менять можно.

### Байт признаков `FLGTAB` — работа с нестандартными дисками

По одному байту на привод, значимы четыре разряда:

| Разряд | Действие |
| :-: | --- |
| 0 | **Пропуск дорожек** при поиске — обрабатываются только чётные. Для чтения 40-дорожечных дисков на 80-дорожечном приводе |
| 1 | Обращение **только к нижней стороне** — односторонний привод или односторонний диск |
| 2 | Сектора длиной **2000 байт** вместо 1000. ⚠ **Работа с такими секторами реализована неверно** |
| 3 | Начало первого сектора задаётся задержкой `HOLTIN` от индекса, иначе — своим заголовком |

### Чтение-запись по номеру блока (`160004`)

| Вход | |
| --- | --- |
| `R0` | Номер блока |
| `R1` | **Длина массива в словах: положительная — чтение, отрицательная — запись** |
| `R2` | Начальный адрес массива |
| `R3` | Базовый адрес рабочей области |
| `UNIT` в рабочей области | Номер привода |

Блок равен **1000 байт** и в применяемом формате совпадает с сектором; первый сектор
нулевой дорожки нижней стороны — блок 0. При превышении размера сектора драйвер
**автоматически переходит к следующему**, при необходимости на другую сторону
и дорожку; при записи неполного сектора остаток заполняется нулями. Пересчёт
блока в сектор и дорожку совпадает с драйвером `MY` для ДВК.

Возврат — `RTS PC`; **содержимое регистров, кроме `R3`, не сохраняется**.

### Коды ошибок

При ошибке **устанавливается флаг `C`**, а код кладётся в байт **`@#52`**:

| Код | Значение |
| :-: | --- |
| 1 | При чтении — ошибка CRC в зоне данных; при записи — **установлена защита записи** |
| 2 | Ошибка CRC в зоне заголовка сектора |
| 3 | Нет позиционирования на нулевую дорожку |
| 4 | Ошибка позиционирования |
| 5 | Не найден сектор |
| 6 | Нет диска или диск не вращается |
| 7 | **Прерывание по вектору 4 во время операции** |
| 10 | Не найден адресный маркер |
| 11 | Не найден маркер данных |
| 12 | Недопустимые параметры команды или нестандартный формат диска |
| 13 | Попытка считывания скрытых данных без разрешения |

### Предупреждения, которых нет в заводской документации

* **Двигатель остаётся включённым** после операции. Гасить его должна программа
  пользователя, обнулив `@#177130` и `CSRW`.
* ⚠ **Не выключайте двигатель командой `RESET`** — просьба автора: `RESET` бьёт
  по всей магистрали, а на БК-0010 с дополнительным ОЗУ это чревато.
* **Прерывание по вектору 4 при записи портит сектор**, в который шла запись.
  Устраняется повторной записью этого сектора.
* ⚠ При записи следите за `SECLEN`: **неверное значение портит разметку диска**.

### Прошивки 253 и 326

| | 253 | 326 |
| --- | :-: | :-: |
| Приводы при автозагрузке | 0…3 | 0, 1 |
| `TRKCOR` при инициализации | 30д | **32д** |
| `BRETRY` при инициализации | 30д | **20д** |
| `MAXSEC` заполняется | нет | **да** |
| Эмулятор расширенной арифметики | нет | **есть** |

Прошивка 253 использует `EMT 0`, `16`, `122`, и их приходится перехватывать:
`EMT 112` заменяется на `NOP`, `EMT 0` восстанавливает стек.

## 14.2.5. Альтернативный контроллер: КНГМД «Комкон» [ПерифБК]

Наряду со штатной линией КНГМД/СМК (глава [../17-контроллер-СМК.md](../17-контроллер-СМК.md))
существовал независимо разработанный контроллер **«Комкон»** зеленоградской фирмы того же
названия — конструктивно две платы «этажеркой» в металлическом корпусе обычной высоты.
Построен **на той же микросхеме 1801ВП1-128**, что и штатный КНГМД, но это не делает
его совместимым:

* **формат дискет — RT-11**, а не тот, что использует драйвер 326 (§14.2.4);
* ОЗУ контроллера отображается в диапазон **`160000`…`167777`** — другое окно, чем у
  штатного КНГМД/СМК;
* **схема подключения аналогична УКНЦ**, а не БК — программы, обращающиеся к диску
  напрямую (минуя стандартный драйвер), на «Комконе» не работают.

Из-за этой несовместимости для запуска обычного БК-софта потребовался сторонний
**эмулятор прошивки 326** поверх контроллера «Комкон» — то есть штатный протокол
драйвера НГМД воспроизводился программно поверх иначе устроенного железа.
